# Docker Compose в DCM

DCM преобразует модель Compose в управляемые контейнеры, тома и сборки, а также управляет жизненным циклом проекта. Это не полноценная среда выполнения Docker Compose: поддерживается безопасное подмножество директив.

## Источники

| Источник | Допустимый формат |
| --- | --- |
| Отдельный файл | `.yml` или `.yaml`, только если проект не использует `build` |
| Архив | `.zip`, `.tar`, `.tar.gz`, `.tgz`; содержит файл Compose и контексты сборки |
| Git | Публичный репозиторий на разрешённом host, optional ref и путь к файлу Compose |

По умолчанию DCM ищет `docker-compose.yml`. Для архива или Git можно указать относительный путь к другому файлу Compose. Абсолютные пути и `..` запрещены.

## Поддерживаемые директивы

На верхнем уровне используются `name`, `services` и `volumes`. Для service поддерживаются:

- `image`;
- `build.context`, `build.dockerfile`, `build.args`;
- `environment`;
- `command` и `entrypoint`;
- `restart` со значениями `no` или `on-failure`;
- `depends_on` и условия зависимостей;
- `healthcheck`;
- именованные `volumes`;
- `labels` для маршрутизации DCM;
- безопасные значения `network_mode`, `pid`, `privileged` проходят дополнительную проверку.

Неподдерживаемые поля не следует использовать: DCM нормализует Compose model до поддерживаемого набора и не гарантирует их сохранение.

## Запрещённые возможности

DCM отклоняет:

- `network_mode: host`;
- `pid: host`;
- `privileged: true`;
- абсолютные подключения каталогов сервера и другие подключения файловой системы сервера;
- нестандартные драйверы томов и их параметры;
- контексты сборки или пути к Dockerfile, выходящие за корень исходных файлов;
- сервисы без `image` и без `build`.

Проброс портов сервера не является способом публикации в DCM. Используйте метки маршрутизации.

## Публикация сервиса

Для публикации задайте обе метки:

```yaml
services:
  web:
    image: nginx:alpine
    labels:
      dcm.domain_prefix: compose-web
      dcm.internal_port: "80"
```

Если указана только одна метка, развёртывание отклоняется. Префикс должен быть допустимым, уникальным внутри проекта и свободным во всей платформе.

## Сборки

Отдельный файл Compose не содержит контекста сборки, поэтому `build` разрешён только при загрузке архива или исходных файлов из Git.

```yaml
services:
  web:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        APP_ENV: production
```

Контекст задаётся относительно каталога файла Compose или исходных файлов. Путь к Dockerfile задаётся относительно контекста. DCM создаёт отдельную задачу сборки, ожидает её завершения и только затем продолжает развёртывание.

## Зависимости и проверки работоспособности

`depends_on` определяет порядок запуска. DCM поддерживает ожидаемые условия зависимости; неизвестное или пустое условие заменяется ожиданием запуска.

Интервал проверки `healthcheck` должен быть не меньше `5s`, а время ожидания — не меньше `2s`. Если зависимый сервис должен перейти в состояние `healthy`, убедитесь, что его образ содержит команду проверки.

## Тома

### Том проекта

```yaml
services:
  db:
    image: postgres:17-alpine
    volumes:
      - db-data:/var/lib/postgresql/data

volumes:
  db-data: {}
```

DCM создаёт управляемый том и ждёт состояния `available` перед созданием зависящих от него контейнеров.

### Существующий том DCM

Сначала создайте том в веб-интерфейсе, затем используйте его пользовательское имя:

```yaml
volumes:
  data:
    external: true
    name: shared-data
```

Внешний том ищется только среди томов текущего владельца. Внутреннее имя тома Docker использовать не требуется. При удалении проекта не удаляются ни тома проекта, ни внешние тома.

## Жизненный цикл проекта

- Развёртывание создаёт сохраняемую задачу и возвращает управление до её завершения.
- Запуск и остановка управляют контейнерами в порядке зависимостей.
- Отмена останавливает активный процесс Compose и связанные сборки, если это возможно.
- Удаление удаляет контейнеры и запись проекта, но сохраняет тома.
- Ошибка отдельного шага сохраняется в `last_error`; после устранения причины создайте новое развёртывание либо выполните доступное действие над проектом.
