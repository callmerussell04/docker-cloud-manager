# Диагностика

Начните с безопасного набора команд:

```bash
docker compose --env-file backend/.env config --quiet
docker compose --env-file backend/.env ps
docker compose --env-file backend/.env logs --tail=200 gateway core sso builder telemetry
df -h
docker system df
```

## Быстрая таблица

| Симптом | Что проверить | Типичное решение |
| --- | --- | --- |
| `port 80 is already allocated` | `sudo ss -ltnp '( sport = :80 )'` | Остановить службу, занимающую порт, или изменить схему входящего прокси-сервера |
| `non-overlapping IPv4 address pool` | `/etc/docker/daemon.json`, `docker network ls` | Настроить непересекающийся `default-address-pools` и перезапустить Docker |
| Интерфейс доступен, поддомен приложения — нет | DNS с подстановочным знаком, префикс, внутренний порт | Исправить `*.BASE_DOMAIN`, дождаться завершения публикации, проверить порт приложения |
| Проверка готовности возвращает `503` | Ответ `checks` и журналы зависимых служб | Восстановить недоступную зависимость Core, SSO или Telemetry |
| Сборка долго остаётся в `pending` | RabbitMQ, Builder, MinIO и журналы Core | Восстановить зависимую службу; не отправлять повторные сборки до проверки очереди |
| Compose долго выполняется | Состояние проекта и сборок, журналы Core и Builder | Исправить сборку, зависимость или проверку работоспособности либо отменить активное развёртывание |
| Операция отклонена из-за квоты | Квота пользователя и зарезервированные ресурсы | Освободить ресурсы или изменить квоту |
| Операция отклонена из-за ресурсов или диска | Административный мониторинг, `df`, активные сборки | Освободить ресурсы сервера; увеличение квоты пользователя не устранит нехватку ресурсов сервера |
| Журналы или терминал не открываются | Состояние контейнера, срок действия билета, источник страницы | Запустить контейнер, повторно получить билет доступа, исправить разрешённый источник |
| Клиентская часть обращается к старому API | Аргументы сборки клиентской части | Пересобрать клиентскую часть после изменения URL или домена |

## Службы не запускаются или проверка готовности возвращает 503

Получите тело ответа проверки готовности и журналы зависимых служб:

```bash
curl -sS -H 'Host: dcm.example.com' http://127.0.0.1/health/ready
docker compose --env-file backend/.env ps
docker compose --env-file backend/.env logs --tail=200 gateway core sso telemetry
```

Проверьте одноразовые задания миграций. При ненулевом коде завершения исправьте строку подключения, учётные данные или ошибку схемы до перезапуска зависимых служб.

## PostgreSQL или ClickHouse не проходят проверку работоспособности

- Проверьте свободное место и права доступа к тому.
- Сверьте пароли в `.env` с уже инициализированными томами. Замена пароля базы данных в переменных окружения не меняет пароль внутри существующей базы.
- Не удаляйте том для устранения ошибки аутентификации.
- Для ClickHouse отдельно проверьте журналы `migrate_reports` и `clickhouse`.

## RabbitMQ, MinIO или реестр образов недоступны

- RabbitMQ влияет на очереди операций жизненного цикла и сборки.
- MinIO используется для подготовки архивов и хранения журналов сборки, но его недоступность не должна останавливать всю платформу.
- Реестр образов необходим для пользовательских образов и их загрузки при запуске контейнеров.

```bash
docker compose --env-file backend/.env logs --tail=200 rabbitmq minio registry builder core
```

Проверьте соответствие `RABBITMQ_PASSWORD`, учётных данных MinIO и объектного хранилища, а также адресов реестра образов. Не меняйте сохранённые учётные данные без отдельной процедуры смены секретов.

## Контейнер имеет состояние `missing`

Ресурс Docker был удалён или изменён вне DCM. DCM сохраняет запись в базе данных и `last_error`, чтобы потеря ресурса не выглядела как штатное удаление. Такой ресурс нельзя запустить; удалите запись через DCM и создайте контейнер заново.

## Сборка или Compose завершились ошибкой

1. Откройте журналы сборки и `last_error` проекта.
2. Проверьте структуру архива, контекст сборки и путь к Dockerfile.
3. Для Git убедитесь, что URL использует HTTPS, не содержит учётных данных, а сервер входит в список разрешённых.
4. Для Compose сравните файл с [поддерживаемыми директивами](compose-guide.md#поддерживаемые-директивы).
5. Проверьте ограничения подготовленных данных, очереди и диска, а также доступность сборок.

## Журналы и терминал

- Журналы доступны только для допустимых состояний контейнера.
- Терминал доступен только в состоянии `running`.
- Источник соединения WebSocket должен входить в `CORS_ALLOWED_ORIGINS`.
- Команда должна входить в список, разрешённый рабочими настройками, и присутствовать внутри образа.

## После изменения домена остался старый URL

`FRONTEND_API_URL` и `BASE_DOMAIN` встраиваются во время сборки:

```bash
docker compose --env-file backend/.env up -d --build frontend gateway core
```

Очищайте кеш браузера только после успешной пересборки и проверки созданной клиентской части.
