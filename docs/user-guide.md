# Руководство пользователя

Руководство описывает работу в веб-интерфейсе DCM с ролью `user`. Доступные ресурсы ограничиваются квотами, назначенными администратором, и свободными ресурсами сервера.

## Вход и регистрация

- Вход по имени пользователя и паролю отображается, если администратор включил `SSO_LOCAL_LOGIN_ENABLED`.
- Самостоятельная регистрация доступна при `SSO_LOCAL_REGISTER_ENABLED=true`.
- Вход через Keycloak отображается при включённом OIDC.
- Деактивированный пользователь не может войти, обновить токен доступа или выполнять запросы к API.

Токен доступа хранится в клиентской части приложения, а токен обновления — в файле cookie с атрибутом HttpOnly. Токены не передаются в URL.

## Главная панель и квоты

Главная панель показывает количество и состояние ресурсов, зарезервированную память, использование диска и назначенные квоты. Операция может быть отклонена даже при свободной пользовательской квоте, если серверу не хватает оперативной памяти, процессорного времени или места на диске.

При отказе освободите неиспользуемые ресурсы либо обратитесь к администратору. Повторная отправка одинаковых запросов не увеличивает доступную ёмкость.

## Состояния и асинхронные операции

Создание, запуск, остановка, публикация и удаление ресурсов выполняются асинхронно. Успешный ответ интерфейса означает, что операция поставлена в очередь, а не завершена в Docker.

Типичные состояния:

| Состояние | Значение |
| --- | --- |
| `pending`, `creating` | Ресурс зарезервирован и ожидает фонового обработчика |
| `running` | Контейнер или задача выполняется |
| `exited`, `stopped` | Ресурс остановлен штатно |
| `deleting` | Удаление поставлено в очередь |
| `failed`, `error` | Операция завершилась ошибкой; проверьте сообщение и журналы |
| `canceled` | Сборка или развёртывание Compose отменено пользователем |
| `missing` | Ресурс Docker исчез вне DCM; запись можно удалить, но использовать нельзя |

Дождитесь конечного состояния перед зависимой операцией. Страницы ресурсов обновляют состояние с сервера.

## Тома

1. Откройте раздел **Volumes** («Тома»).
2. Создайте том с уникальным именем.
3. Дождитесь состояния `available`.
4. При создании контейнера выберите том, укажите абсолютный mount path внутри контейнера и при необходимости включите read-only режим.

Том нельзя удалить, пока он используется контейнером. Удаление проекта Compose не удаляет его тома: они остаются на странице **Volumes**. Внешний том Compose определяется по пользовательскому имени в рамках текущего владельца.

## Контейнеры

### Создание

На странице **Containers** укажите:

- уникальное имя;
- ссылку на публичный образ, например `nginx:alpine`, либо тег образа, собранного в DCM;
- необязательный префикс домена и внутренний порт;
- переменные окружения;
- подготовленные подключения томов.

Прямой проброс портов сервера не используется. Для публикации DCM подключает контейнер к `proxy_net` и создаёт маршрут Traefik.

### Публикация

Для опубликованного контейнера обязательны оба значения:

- префикс домена, например `my-app`;
- порт, который приложение слушает внутри контейнера, например `8080`.

Результирующий URL: `http://my-app.<BASE_DOMAIN>`. Префикс должен быть уникальным и не входить в список зарезервированных или запрещённых значений, заданный администратором.

### Управление

- **Start** («Запустить») создаёт асинхронную операцию запуска и повторно проверяет доступность ресурсов.
- **Stop** («Остановить») останавливает контейнер, сохраняя его запись и подключённые тома.
- **Delete** («Удалить») удаляет контейнер после проверки владельца.
- Успешно завершившийся одноразовый контейнер переходит в состояние `exited`; ненулевой код завершения или нехватка памяти приводит к состоянию `error`, если остановка не была запрошена.

### Метрики, журналы и терминал

Статистика процессора, оперативной памяти и сети доступна для созданного контейнера. Журналы открываются через SSE, а терминал — через WebSocket и только для контейнера в состоянии `running`.

Перед открытием потока клиентская часть получает короткоживущий одноразовый билет доступа. В терминале можно выполнять только команды из списка, разрешённого администратором. Привилегированный режим не используется, JWT не передаётся в URL. После работы закройте диалоговое окно, чтобы завершить соединение.

## Образы и сборки

### Сборка из архива

Поддерживаются `.zip`, `.tar`, `.tar.gz` и `.tgz`. Укажите:

- тег образа, например `my-app:v1`;
- контекст сборки относительно корня архива, по умолчанию `.`;
- путь к Dockerfile относительно контекста, по умолчанию `Dockerfile`;
- аргументы сборки, если они действительно нужны Dockerfile;
- архив с исходным кодом.

Поля с метаданными обрабатываются до файла архива. Размеры загружаемого файла, архива, распакованных данных и журналов ограничиваются настройками, изменяемыми во время работы.

### Сборка из Git

Поддерживаются только публичные репозитории по HTTPS без учётных данных, личных токенов доступа, SSH и подмодулей. Имя сервера должно присутствовать в `git_allowed_hosts`. Можно указать ветку или другую ссылку Git, контекст сборки, Dockerfile и аргументы сборки.

### Состояние сборки

Сборка выполняется фоновым обработчиком через Kaniko. На вкладке сборок доступны состояние, журналы и отмена. `canceled` является отдельным конечным состоянием. После успешной сборки образ появляется в списке и становится доступен при создании контейнера.

Не передавайте секреты через аргументы сборки: они могут попасть в слои образа. Использование существующего тега обновляет соответствующий образ после успешной сборки.

## Проекты Compose

На странице **Projects** («Проекты») можно загрузить отдельный файл `.yml`/`.yaml`, архив либо указать публичный репозиторий Git. Подробный формат, ограничения и примеры приведены в [руководстве по Compose](compose-guide.md).

Развёртывание, запуск, остановка и удаление проекта выполняются асинхронно. Отмена применяется к активному развёртыванию. При удалении проекта удаляются его контейнеры, но сохраняются тома.

## Ошибки

Интерфейс показывает безопасное сообщение для пользователя. Внутренние ошибки Docker и базы данных, `request_id` и служебные коды не отображаются.

## Минимальная проверка основных возможностей

1. Создайте том `smoke-data` и дождитесь состояния `available`.
2. Создайте контейнер из образа `nginx:alpine` и подключите том к `/data` в режиме «только для чтения».
3. Опубликуйте контейнер с помощью свободного префикса и порта `80`.
4. Дождитесь состояния `running`, откройте URL, статистику и журналы.
5. Откройте терминал, если в образе присутствует разрешённая командная оболочка.
6. Остановите и снова запустите контейнер.
7. Удалите контейнер, затем том.
